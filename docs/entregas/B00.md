## Reprodução e limites

- Ambiente de QA: Windows/PowerShell, SDK .NET 10.0.401, Node 24.18.0, npm 12.0.1, Vite 7.3.7. Chromium/headless shell 1248 e FFmpeg 1013 instalados por `npx playwright install chromium`. E2E válido: `npm run test:e2e -- --timeout=20000 --global-timeout=90000`, 6,9 s. As tentativas iniciais foram interrompidas ou falharam por navegador ausente; não foram contabilizadas como aprovação.
- O build .NET restrito falhou sem diagnóstico e a primeira repetição foi interrompida; a repetição autorizada concluiu com código 0, sem erros ou avisos. O npm restrito falhou com ENOTFOUND; repetição autorizada restaurou dependências. A validação temporária com `@apidevtools/swagger-cli` 4.0.4 teve código 0 após repetição autorizada (primeira tentativa ENOTFOUND); não foi incorporada à B00.
- HTTP do host de QA em 15080: respostas 200/200/503/404 conforme a matriz com banco indisponível. Depois de disponibilizar Rancher Desktop, Docker 29.5.3 executou `postgres:17-alpine` (digest `sha256:266d3c257594e195b309ae9d1805e54c788f1d7b375f56bf6c367aac6c917e7b`) em container exclusivo, tmpfs, loopback 15439 e credenciais sintéticas. Após `pg_isready`, o mesmo host retornou readiness 200. Script e remoção do container próprio terminaram com código 0; portas sem listeners. Consulta adicional `docker ps` ficou inconclusiva, sem ser usada como prova de limpeza. Nenhum banco ou volume existente foi tocado.
- A execução conjunta de todos os serviços Compose não ocorreu e não integra o aceite de configuração da B00. Autorização privada, concorrência, migrations, jornadas reais e auditoria completa de acessibilidade pertencem a histórias posteriores. O [relatório inicial](../validacao.md) permanece como contexto histórico, sem substituir o parecer desta rodada.
